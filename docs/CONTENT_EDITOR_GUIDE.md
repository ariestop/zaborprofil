# Руководство контент-редактора

Контент переносится вручную из текущего WordPress-сайта. Автоматический WordPress importer в проекте не создается.

Будущая работа редактора:

1. В списке страниц нажать «Создать страницу», ввести название (адрес построится сам) и выбрать раздел сайта.
2. Выбрать шаблон карточкой; внизу окна виден состав шаблона. Для «Пустой страницы» выбрать тип.
3. «Создать и открыть»: стартовые блоки из шаблона добавятся автоматически, тексты-заготовки отмечены в редакторе — замените их на свои.
4. Заполнить SEO-поля.
5. Проверить SEO-чеклист.
6. Открыть preview-ссылку и проверить блоки, breadcrumbs и lead-форму.
7. Отправить на review или опубликовать, если есть право.

## Шаблоны, дублирование и массовые действия

- **Шаблоны страниц.** При создании страницы выберите шаблон карточкой: «Забор из профнастила», «Забор-жалюзи», «Ворота и калитки», «Страница услуги» и другие; тип страницы берётся из шаблона. Шаблон создаёт набор блоков с готовой структурой; подсказки показывают, что нужно заменить.
- **Сохранить страницу как шаблон.** В меню рядом с кнопкой «Опубликовать» пункт «Сохранить страницу как шаблон» сохраняет все блоки страницы. Шаблон появится при создании страниц того же типа. Тексты и картинки копируются как есть.
- **Секции.** Выберите блок и нажмите «Сохранить как шаблон секции». Затем на любой странице в окне «Добавить блок» ссылка «Вставить секцию из шаблона» добавит блоки после выбранного блока или в конец страницы. Пользовательские шаблоны секций можно удалить из этого же окна.
- **Дублирование.** В списке страниц пункт «Дублировать» в меню «⋯» строки создаёт черновик с теми же блоками и SEO. Адрес получает суффикс `-copy`, canonical не копируется. После создания откроется редактор копии: измените название, адрес и тексты.
- **Массовые действия.** В списке страниц отметьте страницы галочками: можно сменить статус (черновик, на проверке, одобрено, снято с публикации, архив) и закрыть или открыть страницы для индексации. Публикация выполняется только по одной странице после проверки SEO.

## Текущая модель Content Engine

Страница состоит из `Page` и набора `PageBlock`.

`Page` хранит:

- тип страницы;
- заголовок;
- slug;
- ручной URL `path`;
- h1;
- статус;
- шаблон;
- признак индексации;
- SEO-поля: SEO-title (отдельный заголовок для поиска и вкладки браузера; если пуст — используется шаблон по умолчанию из «Настройки → Шаблон SEO-title» или название страницы), meta description, canonical URL, OpenGraph и JSON-LD. Под полями показываются счётчики длины и превью сниппета; H1 от SEO-title не зависит.

`PageBlock` хранит:

- тип блока;
- название;
- позицию;
- признак включения;
- `content` в JSON;
- `settings` в JSON.

Блоки выводятся по `position`. Отключенные блоки не попадают в публичный рендер.

Черновики публично не показываются. Чтобы страница открылась по своему URL, ее нужно опубликовать.

При публикации создается revision — снимок страницы, SEO и блоков. История
публикаций доступна в редакторе страницы; rollback восстанавливает выбранную
revision как новый черновик, а не переписывает историю.

## Публичная форма заявки

На публичных CMS-страницах выводится lead-форма. Редактору нужно проверить:

- форма визуально уместна на странице;
- текст согласия соответствует опубликованной политике;
- preview не индексируется, но показывает будущую форму;
- после публикации тестовая заявка попадает в `/admin/leads`.

Spam-заявки могут появиться со статусом `spam`; это нормальная работа антиспам-слоя.

## Preview

Черновик можно открыть через preview-ссылку из админки. Preview:

- не попадает в публичный кэш;
- отдаёт `X-Robots-Tag: noindex,nofollow`;
- показывает текущие блоки и SEO-поля до публикации.

## Статусы Страниц

- `draft` — черновик, публично не открывается.
- `review` — ожидает проверки редактором/SEO.
- `approved` — одобрено, но не опубликовано.
- `published` — опубликованная страница, доступна по `path`.
- `scheduled` — запланировано.
- `unpublished` — снята с публикации.
- `archived` — архивная страница, публично не открывается.
- `deleted` — soft deleted.

Переходы выполняются кнопкой «Публикация и расписание» в шапке редактора страницы: `draft → review → approved → published` или
`approved → scheduled` с датой публикации (и необязательной датой снятия). У опубликованной страницы можно запланировать снятие.
Недоступные по ролям переходы показываются отключёнными. Публикацию и снятие по расписанию выполняет планировщик
(`app:content:publish-scheduled`, раз в минуту); при сбое SEO-чек-листа страница возвращается в `approved`, причина видна в журнале событий.
На вкладке «История» можно сравнить ревизию с текущей версией (текст, SEO, блоки) и восстановить её.
Подробности: [50-publishing-workflow](50-publishing-workflow.md).

## Типы Блоков

В проекте поддерживаются два семейства типов:

- legacy (`hero`, `text`, `feature_grid`, `cta_form`, `contacts`, ...);
- structured builder (`hero.classic`, `rich-text`, `features`, `contact-form`, `cta`, ...).

Публичный рендер умеет работать с обоими форматами: каждый тип выводится своим шаблоном
`templates/public/blocks/{type}.html.twig`; незаполненные галереи и списки работ на сайт не выводятся.

Для редактора это означает: используйте типы из builder (они приоритетны), а
legacy остаются для совместимости и поэтапной миграции старого контента.

## Визуальный редактор `text` и `text_image`

В админке для блоков `text` и `text_image` доступен визуальный режим на базе
Vue TipTap.

Поддерживается:

- редактирование заголовка и rich-text содержимого;
- базовое форматирование: жирный, курсив, H2/H3, маркированный и нумерованный списки, цитата, ссылка;
- сохранение rich-text как HTML в `content.text`;
- fallback в режим `JSON` для нестандартных кейсов;
- для `text_image` — выбор изображения из Media Library и заполнение `alt`;
- в TipTap: «Загрузить» (файл попадает в Media Library) и «Медиатека» (вставка уже загруженного изображения); в блоках Builder у каждого поля изображения есть выбор из медиатеки; изображение для соцсетей (OG) выбирается там же.

## URL

`path` задается вручную и должен сохранять SEO-совместимость со старым сайтом, например:

- `/zabor-jaluzi/`
- `/zabor-iz-profnastila/`
- `/fasad/profnastil/`
- `/contacts/`

`slug` валидируется отдельно и должен состоять из латинских букв в нижнем регистре, цифр и дефисов.
