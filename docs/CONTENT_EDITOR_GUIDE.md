# Руководство контент-редактора

Контент переносится вручную из текущего WordPress-сайта. Автоматический WordPress importer в проекте не создается.

Будущая работа редактора:

1. Создать страницу.
2. Выбрать тип страницы и шаблон.
3. Создать стартовые блоки из шаблона.
4. Заполнить SEO-поля.
5. Проверить SEO-чеклист.
6. Открыть preview-ссылку и проверить блоки, breadcrumbs и lead-форму.
7. Отправить на review или опубликовать, если есть право.

## Текущая модель Content Engine

Страница состоит из `Page` и набора `PageBlock`.

`Page` хранит:

- тип страницы;
- заголовок;
- slug;
- ручной URL `path`;
- h1;
- статус;
- шаблон;
- признак индексации;
- SEO-поля: meta description, canonical URL, OpenGraph и JSON-LD.

`PageBlock` хранит:

- тип блока;
- название;
- позицию;
- признак включения;
- `content` в JSONB;
- `settings` в JSONB.

Блоки выводятся по `position`. Отключенные блоки не попадают в публичный рендер.

Черновики публично не показываются. Чтобы страница открылась по своему URL, ее нужно опубликовать.

При публикации создается revision — снимок страницы, SEO и блоков. История
публикаций доступна в редакторе страницы; rollback восстанавливает выбранную
revision как новый черновик, а не переписывает историю.

## Публичная форма заявки

На публичных CMS-страницах выводится lead-форма. Редактору нужно проверить:

- форма визуально уместна на странице;
- текст согласия соответствует опубликованной политике;
- preview не индексируется, но показывает будущую форму;
- после публикации тестовая заявка попадает в `/admin/leads`.

Spam-заявки могут появиться со статусом `spam`; это нормальная работа антиспам-слоя.

## Preview

Черновик можно открыть через preview-ссылку из админки. Preview:

- не попадает в публичный кэш;
- отдаёт `X-Robots-Tag: noindex,nofollow`;
- показывает текущие блоки и SEO-поля до публикации.

## Статусы Страниц

- `draft` — черновик, публично не открывается.
- `review` — ожидает проверки редактором/SEO.
- `approved` — одобрено, но не опубликовано.
- `published` — опубликованная страница, доступна по `path`.
- `scheduled` — запланировано.
- `unpublished` — снята с публикации.
- `archived` — архивная страница, публично не открывается.
- `deleted` — soft deleted.

## Типы Страниц

Поддерживаются базовые типы:

- `home`
- `landing`
- `service`

## Типы Блоков

В enum уже заведены основные типы блоков: `hero`, `text`, `text_image`, `image`, `gallery`, `video`, `price_cards`, `feature_grid`, `steps`, `faq`, `cta_form`, `telegram_cta`, `contacts`, `map`, `portfolio_grid`, `seo_text`, `html_embed`, `table`, `accordion`, `quote`, `before_after`, `calculator_placeholder`.

Сейчас Twig partials добавлены для `hero`, `text`, `seo_text` и fallback `default`. Остальные partials будут расширяться при разработке визуального редактора и публичного дизайна.

## Визуальный редактор `text` и `text_image`

В админке для блоков `text` и `text_image` доступен визуальный режим на базе
Vue TipTap.

Поддерживается:

- редактирование заголовка и rich-text содержимого;
- базовое форматирование: жирный, курсив, H2/H3, маркированный и нумерованный списки, цитата, ссылка;
- сохранение rich-text как HTML в `content.text`;
- fallback в режим `JSON` для нестандартных кейсов;
- для `text_image` — выбор изображения из Media Library и заполнение `alt`.

## URL

`path` задается вручную и должен сохранять SEO-совместимость со старым сайтом, например:

- `/zabor-jaluzi/`
- `/zabor-iz-profnastila/`
- `/fasad/profnastil/`
- `/contacts/`

`slug` валидируется отдельно и должен состоять из латинских букв в нижнем регистре, цифр и дефисов.
