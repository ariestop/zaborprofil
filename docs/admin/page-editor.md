# Единый редактор страницы

Редактирование страницы собрано на одном экране вместо трёх прежних (список с модалками, карточка страницы, отдельный Builder).

## Маршруты

| Путь | Назначение |
| --- | --- |
| `/admin/pages` | Список страниц (см. ниже) |
| `/admin/pages/new` | Окно «Новая страница» поверх списка: название, адрес (строится из названия, «изменить» открывает slug и path), раздел сайта, шаблон карточкой. Тип страницы берётся из шаблона, у «Пустой страницы» выбирается вручную. Страница создаётся черновиком, стартовые блоки — из шаблона; «Создать и открыть» ведёт в редактор, закрытие окна — обратно к списку |
| `/admin/pages/:id` | Редактор, вкладка «Контент» |
| `/admin/pages/:id/seo` | Вкладка «SEO» |
| `/admin/pages/:id/settings` | Вкладка «Настройки» |
| `/admin/pages/:id/revisions` | Вкладка «История» (ревизии) |
| `/admin/pages/:id/builder` | Совместимость со старым URL: открывает вкладку «Контент» |

Неизвестный сегмент после `:id` перенаправляет на `/admin/pages/:id`. Маршрут `/admin/pages/new` объявлен раньше `/admin/pages/:id`, поэтому `new` не воспринимается как идентификатор.

Вкладки — это вложенные маршруты под одним постоянным элементом `PageEditor`: переключение вкладок не размонтирует форму и список блоков, поэтому несохранённые правки не теряются.

## Список страниц

- Вкладки статусов со счётчиками: «Все» (без удалённых), «Черновики», «На проверке», «Одобрены», «Опубликованы», «Сняты»; «Запланированы», «В архиве», «Удалённые» появляются, когда такие страницы есть.
- Поиск по названию и адресу, фильтр по типу, сортировка «Сначала изменённые» / «По адресу» / «По названию».
- Колонки: страница и адрес, тип, статус (метки `noindex` и «есть неопубликованные правки»), «Изменена» («сегодня, 14:32» и под датой — кто изменил: имя из профиля пользователя, иначе email).
- Автор правки (`content_pages.updated_by`) проставляется `PageEditorStampListener` при любом сохранении, которое сдвигает `updatedAt` страницы: поля, SEO, статус, блоки. Изменения без администратора (публикация по расписанию, консоль) очищают автора. Для старых страниц автор восстановлен миграцией `Version20261017090000` по журналу действий.
- Меню «⋯» строки: «Редактировать», «Открыть на сайте» или «Предпросмотр», «Дублировать» (`pages.create`), «Снять с публикации» (`pages.unpublish`), «В архив» (`pages.archive`). Смена статуса идёт через `POST /pages/bulk` с одной страницей.
- Галочки и тёмная панель «Выбрано страниц: N»: смена статуса (без публикации), закрыть/открыть для индексации.
- На телефоне — карточки (название, адрес, статус, время правки) и вкладки-«чипы» с прокруткой.

Модули: `admin/pages/PagesPage.tsx`, `admin/features/pages-list/*` (`list-model.ts`, `PageRowMenu.tsx`, `PageCreateDialog.tsx`), `admin/features/page-editor/PagesBulkBar.tsx`.

## Что на каких вкладках

- **Контент** — рабочее место блоков: структура страницы, предпросмотр «как на сайте» и поля выбранного блока (подробно — [page-builder](page-builder.md)). Вкладка занимает всю ширину экрана (`fullBleed` в `route-config.ts`), остальные вкладки — карточка шириной до `max-w-5xl`.
- **SEO** — `metaTitle`, `metaDescription` со счётчиками длины, превью сниппета (из B1), canonical, OG-заголовок/описание/изображение (MediaPicker из C1), JSON-LD (только в расширенном режиме) и SEO-аудит страницы.
- **Настройки** — название, H1, тип, шаблон, slug, path, родитель, порядок, видимость, индексация и быстрые смены статуса (вернуть в черновик, снять с публикации, в архив, удалить).
- **История** — ревизии, сравнение с текущей версией и восстановление выбранной версии.

Шапка: название и статус страницы, адрес (`path`), ссылка «К списку страниц», индикатор сохранения, кнопки «Предпросмотр», «Сохранить» (также `Ctrl/Cmd+S`), «Опубликовать» и меню «Другие действия со страницей» (стрелка рядом с «Опубликовать»): «Публикация и расписание…», «Сохранить страницу как шаблон» (право `pages.manage_templates`) и «Режим JSON (для разработчика)».

Слоты для публикационного workflow (D1) расположены в `admin/features/page-editor/slots.tsx`: `PagePublishingSlot` (шапка) и `PageRevisionsSlot` (вкладка «История»). Реализация D1 подключена в этих компонентах из `admin/features/publishing/`: пункт меню «Публикация и расписание…» открывает панель workflow (`PagePublishingSlot` с `hideTrigger` и `openSignal`; перед открытием сохраняются правки), вкладка «История» дополнена сравнением ревизий с текущей версией. Подробности: [50-publishing-workflow](../50-publishing-workflow.md).

## Сохранение и автосохранение

Состояние формы (настройки + SEO) живёт в одном `react-hook-form`, блоки — в `useBuilderStore`. Индикатор сохранения имеет состояния: «Изменений нет», «Есть несохранённые изменения», «Сохранение…», «Все изменения сохранены», «Не удалось сохранить».

- Автосохранение срабатывает через 20 секунд после последней правки и затрагивает **только SEO и блоки** (`PUT /seo`, `PUT /builder`).
- Поля вкладки «Настройки» (slug, path, шаблон, родитель и т. д.) автосохранением не сохраняются — только кнопкой «Сохранить»: их изменение влияет на URL и структуру сайта.
- Для опубликованных страниц автосохранение выключено: любая правка живого контента — осознанное действие кнопкой «Сохранить».
- Невалидные данные автосохранением не отправляются: индикатор показывает ошибку, пока поле не будет исправлено.
- «Опубликовать» и «Предпросмотр» сначала сохраняют все накопленные правки. Предпросмотр открывает окно синхронно по клику (чтобы его не блокировал браузер) и затем перенаправляет его на подписанную ссылку `GET /preview-link`.
- Серверные ошибки валидации (`422`) подсвечиваются на полях, а редактор переключается на вкладку с ошибкой.

## Защита от потери правок

- При наличии несохранённых изменений браузер показывает стандартное предупреждение `beforeunload`.
- При переходе на другой экран админки (ссылка, «назад») открывается диалог «Есть несохранённые изменения»: «Остаться», «Уйти без сохранения» или «Сохранить и уйти».
- Переходы между вкладками одной страницы предупреждение не вызывают.
- Для работы `useBlocker` SPA использует data router (`createBrowserRouter` + `RouterProvider`, `admin/routes/index.tsx`).

## Конфликты правок и восстановление черновика (D2)

**Оптимистичная блокировка блоков.** `GET /builder` и ответ `PUT /builder` содержат поле `version` — хэш содержимого блоков (`BuilderDocumentVersion`: id, тип, порядок, включённость, `content`, `settings`; не зависит от порядка ключей JSON и служебных меток времени). Редактор запоминает версию и отправляет её в `PUT /builder` как `baseVersion`. Если блоки успели изменить в другой вкладке или другим пользователем, backend отвечает `409` с кодом `EDIT_CONFLICT` и актуальными `version` и `updatedAt`, ничего не записывая. Без `baseVersion` проверка не выполняется (обратная совместимость для скриптов и старых клиентов).

В редакторе конфликт открывает диалог «Страница изменена другим пользователем»:

- «Перезаписать моими правками» — повторное сохранение с актуальной версией сервера;
- «Загрузить с сервера» — локальные правки блоков отбрасываются, форма и блоки перечитываются;
- «Остаться в редакторе» — закрыть диалог; индикатор остаётся в состоянии «Не удалось сохранить», автосохранение не повторяет запрос, пока конфликт не разрешён.

Правки SEO и настроек в проверку версии не входят: версия описывает только блоки.

**Мягкая блокировка «сейчас редактирует X».** Редактор раз в 30 секунд вызывает `POST /admin/api/content/pages/{id}/edit-lock` (`sessionId` — случайный идентификатор вкладки, `takeOver: true` — забрать блокировку), при закрытии — `DELETE` с тем же `sessionId`. Состояние хранится в файловом кэше (пул `cache.page_edit_lock`) и истекает через 90 секунд без heartbeat, поэтому закрытая вкладка не оставляет «вечный» замок. Блокировка только предупреждает (жёлтая плашка с именем редактора и кнопкой «Редактировать здесь») и не запрещает сохранение — защиту от потери данных обеспечивает `baseVersion`. Права: `blocks.edit`; ошибки heartbeat редактор игнорирует.

**Локальный черновик.** Несохранённые правки (блоки, настройки, SEO) через 0,5 с после изменения пишутся в `localStorage` (ключ `zaborprofil:admin:page-draft:{id}`) вместе с версией блоков, от которой начата правка, и удаляются после успешного сохранения. Если при открытии страницы найден черновик, отличающийся от серверного состояния, показывается плашка «Восстановить / Отбросить». Восстановленный черновик сохраняет исходный `baseVersion`: если страница на сервере с тех пор изменилась, сохранение приведёт к диалогу конфликта, а не затрёт чужие правки молча.

**Индикатор сохранения.** Автосохранение не показывает тосты: статус («Есть несохранённые изменения» → «Сохранение…» → «Все изменения сохранены в ЧЧ:ММ:СС» / «Не удалось сохранить» с причиной) выводится в шапке; тост показывается только при ручном сохранении.

## Расширенный режим

Пункт «Режим JSON (для разработчика)» в меню шапки показывает под полями блока JSON-редактор `content`/`settings` и поле JSON-LD на вкладке SEO. Состояние хранится в `localStorage`. Это переключатель интерфейса, а не проверка роли: серверные права (`pages.edit`, `pages.publish`, `seo.edit`) проверяются backend-ом независимо от режима. Блокам без собственной формы JSON больше не нужен: форма строится по их `content` (см. [page-builder](page-builder.md)).

## Исправление parentId

Раньше `PageOutput` не содержал `parentId`, поэтому форма отправляла `parentId: null` и каждое сохранение сбрасывало родителя. Теперь `GET/PUT /admin/api/content/pages` возвращает `parentId`, форма его сохраняет, а выбор родителя исключает саму страницу, её потомков и удалённые страницы. Покрыто тестом `AdminContentApiTest::testPageApiExposesParentIdAndKeepsItOnRoundTrip`.

## Ограничения

- При смене `path` backend создаёт 301 со старого адреса на новый и выключает активный редирект с нового адреса (`PagePathChangeListener`, см. [26-seo-architecture](../26-seo-architecture.md)); правила видны и правятся в `/admin/seo`.
- Права доступа на уровне SPA не скрывают кнопки: недоступные операции возвращают `403`, текст ошибки показывается в уведомлении.
