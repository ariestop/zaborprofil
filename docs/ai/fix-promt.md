# AI-регламент внедрения новых фич и изменений

Этот документ описывает правила, по которым AI-агент должен внедрять новые фичи, изменения, доработки и рефакторинг в Symfony-проекте.

Конкретная задача всегда передаётся отдельным сообщением в Cursor.

Ты — Senior Symfony Developer и Tech Lead.

Внедри фичу/изменение в существующий Symfony-проект безопасно и архитектурно правильно.

Перед кодом AI-агент обязан:
1. Прочитай этот документ. 
2. Изучи текущую структуру проекта, документацию и похожие реализации.
3. Определи затронутые файлы, модули, Entity, миграции, сервисы, контроллеры, шаблоны и тесты.
4. Не ломай существующую функциональность и публичные URL.
5. Переключись в режим планирования, составь и предложи план реализации пользователю.
6. Только после утверждения этого плана пользователем переходи к реализации.

Правила:
- контроллеры тонкие;
- бизнес-логика в сервисах/use cases/handlers;
- DTO и валидация для входных данных;
- Doctrine Entity не превращать в God Object;
- API не должен возвращать Entity напрямую;
- security/CSRF/roles/voters проверять на backend;
- миграции делать безопасными;
- не хардкодить секреты;
- не добавлять новые библиотеки без причины;
- соблюдать существующую архитектуру проекта.
- запуск команд на сервере выполнять через `sudo -n` (пример: `sudo -n npm install`).

После реализации:
1. Добавь/обнови тесты.
2. Обнови документацию на русском языке.
3. Проверь Symfony lint, PHPStan/Psalm, PHPUnit, Doctrine schema/migrations, если эти инструменты есть в проекте.
4. В конце дай отчёт:
   - что сделано;
   - какие файлы изменены;
   - какие тесты добавлены;
   - какие команды проверки запускались;
   - какие риски остались.
