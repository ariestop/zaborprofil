# План: контент и дизайн по zaborprofil.ru

**Обзор:** Перенос контента и дизайна с zaborprofil.ru на новый движок: роутинг страниц из Payload, рендер блоков на фронте, дизайн-система и наполнение страниц текстами со старого сайта. API не трогаем.

---

## Текущее состояние

- **Главная** и все страницы захардкожены в `nextjs/app/page.tsx`; Payload используется только для админки (`/admin`), страницы из коллекции `pages` на фронте не отображаются.
- В Payload есть коллекция **Pages** с блоками: Hero, Text (richText), FAQ, CTA, Grid (`nextjs/collections/Pages.ts`), но **нет кода, который бы получал страницу по slug и рендерил эти блоки** в Next.js.
- Коллекция **Navigation** есть (`nextjs/collections/Navigation.ts`), но в шапке сейчас статичные ссылки (Каталог, Калькулятор, Корзина, Помощник).

Цель: главная и все информационные страницы (Контакты, типы заборов и т.д.) брать из Payload; каталог, калькулятор, корзина, товары остаются отдельными маршрутами Next.js. Внешний вид и тексты — по образцу zaborprofil.ru.

---

## Этап 1. Роутинг и выборка страниц из Payload

### 1.1 Зарезервированные пути

Не отдавать в Payload, оставить за статичными/динамическими маршрутами Next.js:

- `catalog`, `calculator`, `cart`, `checkout`, `chat`, `product` (и сегменты вроде `product/[slug]`), `admin`, `cms-api`, `graphql`, `graphql-playground`, `_next`, `favicon.ico` и т.п.

Логика: один сегмент пути (например `contacts`) — если не зарезервирован, ищем в Payload страницу с `slug === 'contacts'`.

### 1.2 Главная страница

- **Вариант A (рекомендуется):** оставить `nextjs/app/page.tsx` как точку входа; внутри вызывать `getPayload`, искать страницу с `slug: 'home'`. Если найдена — рендерить блоки; если нет — показывать текущий запасной вариант (как сейчас).
- Вариант B: перенести рендер главной в общий механизм «страница по slug», а в корне оставить только редирект или выбор между Payload и fallback.

### 1.3 Динамический маршрут для остальных страниц

- Добавить `nextjs/app/[slug]/page.tsx` (один сегмент).
- В обработчике:
  - если `slug` в списке зарезервированных — `notFound()` или редирект;
  - иначе: `getPayload({ config })`, затем `payload.find({ collection: 'pages', where: { slug: { equals: slug } }, limit: 1 })`;
  - если документ не найден — `notFound()`;
  - если найден — рендерить общий layout (шапка/подвал) + блоки страницы (см. этап 2).

Использовать `getPayload` из `payload` с конфигом `@payload-config` (или `getPayloadHMR` из `@payloadcms/next/utilities` для dev). Для metadata — поля `meta.metaTitle`, `meta.metaDesc`, `meta.ogImage`.

## Этап 2. Рендер блоков на фронте

### 2.1 Типы блоков и компоненты

У каждой страницы в Payload поле `layout` — массив блоков с `blockType` и полями по схеме (`nextjs/blocks/`).

Нужен **маппинг blockType → React-компонент** и общий цикл по `page.layout`.

Предлагаемая структура — папка `nextjs/components/blocks/`:

- `HeroBlock.tsx` — headline, subheadline, ctaText, ctaLink, backgroundImage.
- `TextBlock.tsx` — контент из richText (Lexical JSON). Вариант: рендерер из `@payloadcms/richtext-lexical/react` или на первом этапе поле `rawHtml`/`plainText` в блоке.
- `FAQBlock.tsx` — массив items (question, answer), аккордеон или список.
- `CTABlock.tsx` — title, description, buttonText, buttonLink.
- `GridBlock.tsx` — массив items: title, image, link — карточки (типы заборов на главной).

Типы — из `payload-types.ts` (после генерации) или вручную по полям блоков.

### 2.2 Общий контейнер

Компонент `PageBlocks.tsx`: принимает `layout`, для каждого элемента по `blockType` рендерит соответствующий блок. Неизвестные блоки — пропуск или заглушка.

### 2.3 RichText (Lexical)

- Вариант 1: официальный React-рендерер из `@payloadcms/richtext-lexical` для фронта.
- Вариант 2: в блок Text опциональное поле `plainText`/`html` для простого вывода на первом этапе.

## Этап 3. Дизайн и общий layout по zaborprofil.ru

### 3.1 Визуальные ориентиры

- Шапка: логотип «Забор Профиль», навигация (главная, типы заборов, контакты).
- Главная: слоган; сетка карточек типов заборов; секции с преимуществами; CTA/контакты.
- Цвета и шрифты с zaborprofil.ru перенести в Tailwind/переменные в `nextjs/app/globals.css`.

### 3.2 Общий layout (Header + Footer)

- Компоненты `nextjs/components/layout/Header.tsx`, `nextjs/components/layout/Footer.tsx`.
- Меню: захардкоженный список или выборка из Payload **Navigation** (один глобальный документ, массив items с label и link).
- Обёртка: один layout оборачивает контент главной и страниц из `app/[slug]/page.tsx`.

### 3.3 Стили блоков

- Секции: отступы, фон, сетка. Карточки Grid — единый вид (изображение, заголовок, подзаголовок, кнопка). Единый стиль кнопок и ссылок.

## Этап 4. Наполнение контентом (страницы в Payload)

### 4.1 Список страниц и slug

| Slug | Назначение | Источник контента |
|------|------------|-------------------|
| `home` | Главная | zaborprofil.ru — слоган, карточки типов заборов, преимущества, текстовые блоки, «Почему мы» |
| `contacts` | Контакты | zaborprofil.ru/contacts — ООО «Забор Профиль», адрес, телефон, email, часы; блок «Дилеры» при необходимости |
| `zabor-jaluzi` | Заборы из жалюзи | Текст со страницы |
| `gorizont` | Забор Ранчо | Аналогично |
| `zabor-iz-euroshtaketnika` | Евроштакетник | Аналогично |
| `zabor-iz-profnastila` | Профнастил | Аналогично |
| `zabor-3d-setka` | 3D сетка | Аналогично |
| `zaglushki-plastik` | Заглушки для труб | Аналогично |
| при необходимости | Крепеж для 3Д забора | zaborprofil.ru/krepezh-3d-zabor/ |

### 4.2 Структура главной (home) в виде блоков

1. **Hero** — «Забор Профиль», слоган про клиентов и сложные заказы, при необходимости CTA.
2. **Grid** — 6 карточек: Жалюзи, Ранчо, Евроштакетник, Профнастил, 3D сетка, Заглушки (title, image, link); при необходимости поле subtitle в Grid.
3. **Text** или **CTA** — «Лидеры монтажных работ», список преимуществ.
4. **Text** — «Качественное изготовление и профессиональный монтаж».
5. **Text** — «Какие заборы можно у нас заказать?», текст + ссылки на страницы типов заборов.
6. **Text** или **CTA** — «Почему стоит заказать в нашей компании?» и список преимуществ.

При необходимости — блок **List** (массив строк или { text, link? }) и `ListBlock.tsx`.

### 4.3 Страница «Контакты»

Один или два блока **Text** (компания, адрес, телефон, email, часы; при необходимости «Дилеры»). Либо отдельный блок **Contacts** со структурированными полями.

### 4.4 Внесение контента

- Вручную: в Payload Admin создать страницы с указанными slug и блоками, скопировать тексты с zaborprofil.ru.
- Полуавтомат: JSON/скрипт импорта в Payload (Local API или seed) — вторая итерация.

## Порядок реализации

1. Роутинг и данные: зарезервированные пути, `getPayload` в `app/page.tsx` (страница `home`), `app/[slug]/page.tsx` с выборкой по slug и `notFound()`.
2. Блоки: компоненты Hero, Text, FAQ, CTA, Grid в `components/blocks/`, маппинг blockType → компонент, PageBlocks. Решение по richText (Lexical или упрощённый вариант).
3. Layout: Header и Footer по образцу zaborprofil.ru, общий layout для главной и [slug], навигация (статичная или из Payload Navigation).
4. Стили: переменные и классы под zaborprofil.ru, оформление блоков и карточек.
5. Контент: создание в Payload страниц home, contacts и страниц типов заборов; при необходимости блок List и расширение Grid.
6. Проверка: обход страниц, ссылки, мобильная вёрстка.

---

## Зависимости и риски

- **Lexical на фронте:** при сложностях — на первом этапе простой текст или поле `html` в блоке Text.
- **payload-types.ts:** генерация типов упростит типизацию блоков и страниц.
- API (каталог, калькулятор) в этом плане не меняется; интеграция каталога с новым дизайном — отдельный шаг после стабилизации контента и вёрстки.
